# 📡 Учебник MikroTik — Android + Windows + интерактивный стенд

Автономное приложение-учебник по настройке роутеров **MikroTik (RouterOS)** с подробными
инструкциями, скриншотами WinBox и готовыми командами CLI — плюс **интерактивный стенд**,
который моделирует конфигурацию под вашу задачу и выдаёт пошаговую инструкцию для
реального роутера.

## Возможности

| Раздел | Содержание |
|---|---|
| 🔌 Подключение провайдера | PPPoE (логин/пароль), DHCP, статический IP, USB 3G/LTE-модем |
| 📶 LAN и Wi-Fi | Подсети, пулы адресов, DHCP, **рабочая и гостевая** Wi-Fi-сети с изоляцией |
| 🛡️ Firewall и NAT | Правила защиты (input/forward), masquerade, порт-форвардинг внутренних ресурсов |
| 🔁 Резервный канал | Авто-переключение при падении основного провайдера и обратно при восстановлении (distance + check-gateway + метки + netwatch) |
| 🧭 Маршрутизация | Статические маршруты, VLAN-сегменты, таблицы и policy routing RouterOS v7 |
| 🔐 VPN | **Все типы MikroTik**: WireGuard, IPsec IKEv2, L2TP/IPsec, site-to-site, PPTP, L2TP, SSTP, OVPN |
| ⚖️ QoS | Simple Queues и PCQ: ограничение скорости клиентов, приоритизация важного трафика (VoIP, видеоконференции) |
| 📊 Мониторинг и диагностика | Netwatch, Torch, системный журнал, графики нагрузки Graphing |
| 🛡️ Система и безопасность | Пользователи и пароли, службы IP Services, обновление RouterOS, бэкап/экспорт, NTP, ip cloud |
| 🖥️ Виртуальная лаборатория | Учебный симулятор RouterOS в браузере: применение конфигурации со стенда на виртуальный роутер без реального железа |
| 🛠 Стенд | Ввод задачи → план адресации → проверка модели → конфигурация RouterOS → инструкция реализации |
| ⌨️ Шпаргалка | Частые команды CLI и приёмы WinBox |

**Стенд моделирования** принимает: подсети LAN/гостевой сети и пулы адресов, тип и количество
провайдеров (PPPoE/DHCP/статика/LTE), основной и резервный канал, тип VPN, список внутренних
IP/портов для публикации наружу (и через какого провайдера), параметры Wi-Fi. На выходе —
проверка исходных данных (пересечения подсетей, конфликты портов, корректность failover),
таблица плана, полная конфигурация RouterOS v7 и чек-лист приёмки.

## Структура репозитория

```
app/                     # общее веб-ядро (общее для Android и Windows)
  index.html             # оболочка + форма стенда
  js/stand.js            # движок моделирования (без DOM, тестируется в Node)
  js/sec-*.js            # контент разделов учебника
  css/app.css            # стили
  assets/img/*.svg       # 23 скриншота WinBox (генерируются tools/gen-screens.js)
android/                 # проект Android (WebView-обёртка, подписанный APK)
windows/                 # проект Windows (Electron, установщик NSIS)
tools/                   # генератор скриншотов и модульные тесты
.github/workflows/       # сборка на GitHub Actions
```

## Сборка на GitHub Actions

Воркфлоу `.github/workflows/build.yml` запускается на **каждый push**:

1. **test** — `node --check` всего JS, регенерация и сверка SVG, `node tools/test-stand.js` (83 проверки), `test-mt` (16), `test-virt` (49), `test-dom` (60);
2. **android** — Gradle 8.4 + JDK 17 → `assembleRelease` → **подписанный APK** → артефакт `MikroTik-Guide-APK`;
3. **windows** — `npm install` + `electron-builder --win` → установщик `MikroTik-Guide-Setup-x.y.z.exe` → артефакт `MikroTik-Guide-Windows`;
4. **release** — при пуше тега `vX.Y.Z` создаётся GitHub Release с обоими файлами.

Скачать свежую сборку:

* **Чистый APK без упаковки** — файл [`releases/MikroTik-Guide.apk`](releases/MikroTik-Guide.apk)
  прямо в репозитории: CI перезаписывает его после каждой успешной сборки ветки (скачивается
  кнопкой Raw/Download файловой страницы GitHub — **без zip**);
* **Releases** — тег `vX.Y.Z` создаёт релиз с файлами `MikroTik-Guide-vX.Y.Z.apk` и
  `MikroTik-Guide-Setup-x.y.z.exe` (оба — чистые файлы, не архивы);
* **Actions → Artifacts** — только Windows-установщик. Важно: GitHub **всегда**
  упаковывает артефакты в zip — это ограничение платформы. Поэтому APK в артефакты
  не выкладывается вовсе, чтобы никто не получал архив вместо установщика:
  Android-сборка живёт только в двух местах выше (релизы и `releases/`) — оба
  отдаются чистым файлом `.apk`.

В приложении есть кнопка **«⟳ Обновить»** (верхняя панель): она сверяет версию с последним
релизом на GitHub и предлагает скачать обновление. На Android запрос выполняется нативным
мостом (без CORS), на десктопе — обычным fetch; при отсутствии сети показывается кнопка
«Страница релизов». APK ставится поверх (тот же ключ подписи), данные сохраняются.

## Порядок версий и релизов

Версия aplikasi synchronizovana vo tri mesta:

| Файл | Поле | Текущее значение |
|------|------|-----------------|
| `app/js/version.js` | `APP_VERSION` | `1.20.0` |
| `android/app/build.gradle` | `versionCode` / `versionName` | `5` / `1.20.0` |
| `windows/package.json` | `version` | `1.20.0` |

**Правила:**

1. **Всегда меняйте версию во всех трёх местах одновременно** — тест `tools/test-stand.js` проверяет их согласованность.
2. **Новая версия должна быть старше всех опубликованных релизов.** Например, если последний релиз `v1.19.1`, новая версия должна быть как минимум `1.20.0` (потому что `1.19.1 > 1.3.0` по семантическому версионированию: второй компонент 19 > 3).
3. При коммите изменений версии на ветку запускается CI: тесты → Android APK → Windows EXE.
4. Для публикации релиза создайте аннотированный тег `vX.Y.Z` (например `git tag -a v1.20.0 -m "..."` и `git push origin v1.20.0`). Workflow `release` соберёт GitHub Release с APK и EXE.
5. APK также коммитится в `releases/MikroTik-Guide.apk` после каждой успешной сборки ветки — чистый файл, без zip-упаковки.
6. GitHub Actions всегда упаковывает артефакты в ZIP — поэтому APK не выкладывается в Actions artifacts, а только в релизы и в `releases/`.

Локально:

```bash
node tools/test-stand.js            # тесты стенда/контента
node tools/gen-screens.js           # перегенерация SVG-скриншотов

# Android (нужен JDK 17 и Android SDK 34)
gradle -p android assembleRelease   # APK: android/app/build/outputs/apk/release/

# Windows (нужен Node.js 20+)
cd windows && npm install && npm run dist   # dist/MikroTik-Guide-Setup-*.exe
```

## Подпись (постоянный ключ)

APK подписывается **постоянным ключом**, лежащим в репозитории:

* `android/keystore/release.p12` — PKCS12-кейстор (RSA-2048, самоподписанный сертификат, действует до 2061 г.);
* `android/keystore/keystore.properties` — алиас и пароли, используемые Gradle.

Благодаря одному и тому же ключу каждая новая версия **обновляется поверх предыдущей**
(без удаления данных приложения).

> ⚠️ **Внимание:** ключ и пароли намеренно размещены в открытом репозитории по требованию
> владельца. Любой, кто имеет доступ к репозиторию, может подписывать обновления этого
> приложения. Не используйте этот ключ для приложений с чувствительными данными; для
> публичных магазинов создайте отдельный ключ и храните его в секретах CI
> (`gradle.properties` / `keystore.properties` через GitHub Secrets).

## Требования

* Роутер MikroTik с RouterOS **v6.49+** или **v7.x** (примеры — под v7, отличия отмечены);
* WinBox 4.x (в разделах используется как основной инструмент, все команды дублируются для CLI);
* Android **8.0+** (minSdk 26); Windows 10/11 x64.

## Прямое подключение к физическому MikroTik

В разделе **«Прямое подключение к MikroTik»** (боковое меню) приложение соединяется с реальным роутером
по **RouterOS API** (порт **8728**) или **API-SSL** (порт **8729**):

* настройте хост/IP, порт, пользователя и пароль, нажмите «Подключиться»;
* в консоли выполняйте команды RouterOS (`/ip address print`, `/ip firewall filter print`, `/system identity print` и др.);
* после моделирования на стенде кнопка **«Отправить сгенерированную конфигурацию на роутер»** по порядку шлёт на подключённый роутер все команды из результатов стенда.

Перед первым подключением на роутере нужно включить службу API:
`/ip service enable api` (для API-SSL — также `api-ssl`).

Как это работает под капотом:
* **Android** — нативный мост WebView (`window.mt`) открывает `java.net.Socket` / `SSLSocket`, выполняет логин API (plain-text или challenge-ответ по MD5 при включённом на роутере строгом режиме) и читает ответы. Используется уже заявленное в манифесте разрешение `INTERNET`.
* **Windows (Electron)** — сокеты `net`/`tls` живут только в главном процессе; рендерер в песочнице (`sandbox: true`, `nodeIntegration: false`) обращается к ним через IPC (`preload.js` → `window.mikrotik`).

Пароль передаётся **только** указанному роутеру и никуда больше не уходит. API-SSL на роутерах обычно использует самоподписанный сертификат — приложение принимает такие сертификаты, так что при подключении не через доверенную сеть понимайте риск подмены (MitM).
