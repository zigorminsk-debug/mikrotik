# 1.19.23 — выбор адреса и DNS для ping из CHR

В Windows можно выбрать адрес из проверенной схемы или указать DNS-имя для ping **из запущенной виртуальной CHR**. DNS-запрос из RouterOS требует отдельного согласия; после получения IPv4 нужно ещё раз подтвердить отправку трёх ICMP-запросов на показанный адрес. Ошибка DNS и отсутствие ответов на ping показываются отдельно; ни то ни другое само по себе не доказывает недоступность сайта. Разрешаются только ASCII DNS-имена и IPv4; URL, IPv6 и специальные адреса не поддерживаются. В случае ошибки консоли проверка блокируется до перезапуска CHR, чтобы не продолжать с неопределённым состоянием.

В лаборатории заранее показано объяснение доступности функции на Android и Windows. В списке адресов нарисованных ПК, серверов и принтеров указано, что сами узлы не запущены. На Android настоящий ping в лаборатории пока недоступен. Настоящие виртуальные клиентские устройства и ping между офисами через VPN ещё не интегрированы. Исследования Linux VM и двух офисов — только Windows CI; они не заменяют пользовательскую функцию.

Изолированная CHR не имеет интернета. В интернет-режиме QEMU может обращаться к локальной сети и Windows-хосту; для него, DNS и ping предусмотрены отдельные подтверждения. QEMU NAT может не пропускать ICMP; задержка и причина отсутствия ответа не определяются. Ручные изменения в WebFig не сверяются с моделью.

Оригинальные снимки WinBox всех настроек пользовательской схемы и автоматическое применение к физическому MikroTik по MAC пока не реализованы. В учебнике показан снимок новых полей Windows-приложения с тестовым мостом; оригинальные снимки подтверждений и результатов ещё не добавлены.

Android APK подписан постоянным ключом, который по требованию владельца хранится в репозитории и является публичным. Для обновления поверх нужны прежняя подпись и меньший versionCode. APK публикуется отдельным файлом. Windows-установщик содержит QEMU, исходники и лицензии; образ CHR загружается отдельно после ознакомления с лицензией.
