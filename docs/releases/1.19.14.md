# MikroTik Guide 1.19.14

- В разделе Log добавлен сценарий «Проверить на стенде»: выбор тем system и interface и создание правил журнала с действием memory. Внешний syslog пока не поддерживается. При существующей схеме требуется подтверждение её замены.
- В Windows совместимая схема запускается на виртуальной CHR после отдельных согласий. Сверяются настройки правил, а не фактическое возникновение событий; журнал в памяти не сохраняется после выключения. События могут содержать чувствительную информацию. Физический MikroTik не изменяется.
- [Windows CHR CI 41311181683](https://github.com/zigorminsk-debug/mikrotik/actions/runs/41311181683) применил выбранные темы к одноразовой CHR и сверил правила через REST. [CI 41311210019](https://github.com/zigorminsk-debug/mikrotik/actions/runs/41311210019) получил оригинальный снимок карточки Windows-приложения без запуска CHR; это не снимок WinBox. События и установленный EXE по этому сценарию не проверялись.
- Теговый [Build 41312033003](https://github.com/zigorminsk-debug/mikrotik/actions/runs/41312033003) собрал подписанный APK и Windows-установщик. [Android update 41312033064](https://github.com/zigorminsk-debug/mikrotik/actions/runs/41312033064) проверил обновление 1.19.13 → 1.19.14 через adb на эмуляторе; физический телефон, браузер и системный установщик не проверены.
- Некоторые разделы и функции пока не поддерживаются. Автоматические оригинальные снимки WinBox всех настроек конкретной пользовательской схемы не реализованы; CI-исследования их не заменяют.
- Ключ подписи APK намеренно хранится в репозитории по требованию владельца, он публичен и не доказывает авторство. Устанавливайте только из доверенного источника.
