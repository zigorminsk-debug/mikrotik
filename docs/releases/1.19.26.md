# 1.19.26 — DNS и проверка шлюза виртуальных Linux-клиентов

В Windows при ping из запущенной Linux VM теперь можно ввести не только IPv4, но и DNS-имя. Запрос выполняет выбранная VM с её DNS-настройками — не модель и не Windows-хост. Сначала требуется отдельное подтверждение DNS, затем показывается полученный адрес и запрашивается отдельное подтверждение трёх ICMP-запросов. Если IPv4 не получен или адрес специальный, ping не отправляется; отмена ping не отменяет уже выполненный DNS-запрос. При нескольких IPv4 используется первый ответ. Перед запросом сверяется текущий DNS с выбранным; при изменении DNS запрос блокируется. Для статического клиента останавливается управляющий DHCP-процесс, чтобы он не перезаписывал DNS. Ошибка DNS не доказывает недоступность цели.

При запуске CHR с клиентами приложение дополнительно сверяет маршрут по умолчанию каждой Linux VM с выбранным шлюзом: для DHCP — с настройкой роутера, для статической адресации — с настройкой клиента, включая отсутствие шлюза. Несовпадение останавливает запуск. Наличие маршрута не доказывает доступность шлюза, DNS или интернета.

Остаются ограничения 1.19.25: до четырёх Linux VM ПК/сервера только в поддерживаемой изолированной схеме Windows с DHCP LAN; нет клиентского интернета, принтеров, виртуальных провайдеров или VPN между офисами. Серверные службы не эмулируются. Публичные учётные данные CirrOS и возможность внедрения пакетов другими локальными процессами означают, что сеть не является границей безопасности. Образ скачивается отдельно после согласия и проверки хеша; полнота лицензий компонентов не проверена. Android не запускает реальные VM. Автоматические снимки всех настроек пользовательской схемы в WinBox и применение к физическому MikroTik по MAC пока не реализованы.

Учебник дополнен порядком проверки и ограничениями. Windows-установщик включает QEMU, его исходники и лицензии; APK подписывается постоянным публичным ключом, размещённым в репозитории по требованию владельца.
