# Продолжение работы: приоритеты и отправная точка

Этот файл — краткая рабочая очередь. Проверяйте актуальные требования пользователя,
код, GitHub Actions и начало `HANDOFF.md`; обновляйте этот файл после каждого этапа.
Все необходимые сведения для следующего агента должны быть в репозитории, а не
только в чате или во временном каталоге. Не храните пароли и личные данные.

## Зафиксированные задачи

1. Продолжать учебник с первичной настройки и далее в порядке меню RouterOS,
   особенно LAN, VLAN и Wi-Fi. Каждый шаг требует оригинального подробного снимка
   WinBox соответствующего действия. `screenshot-audit.md` указывает пробелы в
   нумерованных списках; он не учитывает абзацы и динамические инструкции.
   `app/assets/img/own/SOURCES.md` описывает реальные источники изображений.
2. Продолжать Windows-лабораторию с настоящей CHR и выбранными настройками;
   Wi-Fi-радио, LTE, виртуальные клиенты, VPN пользователя и два физических
   роутера ещё не реализованы. Несовместимые настройки блокируются. Два WAN QEMU
   используют одно подключение компьютера, требуют отдельного согласия на каждый
   запуск и не моделируют две физические сети/две карты сервера.
3. Прямое физическое подключение по MAC и отправка схемы остаются отдельной
   незавершённой задачей. При обрыве возможен неизвестный частичный результат;
   сброс конфигурации требует отдельного явного подтверждения. См.
   `physical-router-plan.md`; не считать MNDP или виртуальную CHR физическим тестом.
4. После каждого этапа: документировать, тестировать на GitHub Actions, выпускать
   чистый APK и Windows EXE; сохранять релиз и тег 1.19.2 до нового согласия.
   Русские заметки о релизах хранить в `docs/releases/`. Все сборки только в CI.

## Доступные сведения

- Последний проверенный выпуск: 1.19.5, Android versionCode 31; [релиз](https://github.com/zigorminsk-debug/mikrotik/releases/tag/v1.19.5).
- Учебник: `app/js/sec-initial.js`, `sec-networks.js`, `sec-z-router-menu.js`.
- Лаборатория и изолированный пример CHR: `app/js/lab.js`, `lab-sim.js`,
  `windows/chr/plan.js`, `session.js`, `verify.js`; типы тестов в `ARCHITECTURE.md`.
- DHCP-клиент: открытие меню IP и список со статусом bound имеют собственные
  снимки тестовой CHR. Форма New, поля настройки, выбор и применение изменений,
  IP → Addresses и IP → Routes всё ещё нуждаются в отдельных реальных снимках.
- Проверенное состояние, ссылки на CI и текущие ограничения — `HANDOFF.md`;
  правила работы — корневой `AGENTS.md`; выпуск — `RELEASE.md`.

## Правила для преемника

Не подменяйте поставленную задачу собственным проектом. Не обещайте незавершённые
возможности, не удаляйте данные/ветки, не применяйте команды к физическому роутеру
без отдельного согласия. Любое уточнение или согласованное изменение записывайте в
`HANDOFF.md`, а конкретный следующий шаг и состояние проверок — сюда.
