# Инвентаризация иллюстраций учебника

**Итого:** 115 подразделов; 158 нумерованных пунктов без явной привязки отдельного снимка, 96 с привязкой. Эти цифры не включают действия в абзацах и динамические инструкции.

Создаётся командой `node tools/audit-screens.js` для видимых разделов меню. Это инвентаризация, а не доказательство соответствия: изображения внутри раздела могут показывать другие значения, версию или действие.

Каждый пункт без явной привязки отдельного снимка помечен ниже. Наличие общего изображения в подразделе не подтверждает покрытие пункта. Команды, абзацы, таблицы и действия вне нумерованных списков также требуют ручной проверки.

Графическая лаборатория и интерактивный конструктор создают инструкции динамически: все комбинации устройств и их изображения проверяются отдельно, в эту статическую инвентаризацию они не входят.

### Два виртуальных WAN в CHR через сеть Windows

**Изображения в подразделе:** нет.

- [ ] Добавьте одного MikroTik, двух провайдеров и два ПК. Соединяйте непосредственно с MikroTik в следующем порядке: основной провайдер, первый ПК, второй ПК, резервный провайдер. Порядок линий определяет ether1, ether2, ether3 и ether4 соответственно; ПК на схеме не запускаются как виртуальные машины. — отдельный снимок к пункту не сопоставлен.
- [ ] В настройках основного провайдера выберите «Статический IP», роль «Основной», IP 10.0.2.20/24, шлюз 10.0.2.2 и DNS 10.0.2.3. Для резервного выберите «Статический IP», роль «Резервный», IP 10.0.3.20/24, шлюз 10.0.3.2 и DNS 10.0.3.3. Это адреса виртуальных NAT; не вводите их на физическом оборудовании. — отдельный снимок к пункту не сопоставлен.
- [ ] На обоих ПК выберите DHCP либо задайте разные статические адреса LAN вне DHCP-пула. В настройках MikroTik включите «Резервный интернет с автопереключением», снимите «Учебное переключение на резервный MikroTik» и включите «Задать DNS-серверы вручную»: основной 10.0.2.3, второй 10.0.3.3. Контроль внешнего узла, VPN, Wi-Fi, LTE и IP Cloud пока отключите. NTP можно включить при необходимости: адрес сервера и пояс будут применены, но доступность и синхронизацию нужно проверить отдельно. — отдельный снимок к пункту не сопоставлен.
- [x] В настройках MikroTik нажмите «Открыть RouterOS». — `assets/img/own/chr-button-windows.jpg`; проверить визуально и по версии.
- [x] В предупреждении прочитайте условия сетевого доступа и выберите «Разрешить для этого запуска» только если согласны с доступом к хосту и LAN. Затем ознакомьтесь с лицензией MikroTik и подтвердите запуск. При отказе сеть не включается. — `assets/img/own/chr-network-warning.jpg`; проверить визуально и по версии.
- [ ] В открывшемся WebFig проверьте оба адреса и маршруты: основной distance 1, резервный distance 2. Чтобы проверить переход именно в этой виртуальной CHR, временно отключите ether1, дождитесь активного маршрута резерва и проверьте связь; затем включите ether1 и проверьте возврат. Сохраняйте доступ через отдельное окно управления; закрытие окна удалит временный диск. — отдельный снимок к пункту не сопоставлен.

### Если RouterOS не скачивается или не открывается

**Изображения в подразделе:** нет.

- [ ] Нажмите OK и проверьте всю схему: должен быть ровно один MikroTik, ровно один провайдер и хотя бы один ПК или сервер; соедините их линиями. Если для теста удаляете лишнее устройство, вместе с ним удалятся его линии. Изменяется только учебная схема, не реальные устройства. — отдельный снимок к пункту не сопоставлен.
- [ ] На значке провайдера нажмите ⚙, выберите «Тип подключения → Статический IP» и сохраните. Для учебного примера укажите IP роутера 198.51.100.2/30, шлюз 198.51.100.1 и DNS 1.1.1.1. Под значком должен быть указан IP, а не PPPoE. Эти значения не нужно вводить на физическом роутере. — отдельный снимок к пункту не сопоставлен.
- [ ] На значке MikroTik нажмите ⚙ и снимите галочки «Резервный интернет с автопереключением» и «Учебное переключение на резервный MikroTik». Пока также отключите Wi-Fi, VPN, LTE и другие неподдерживаемые возможности. — отдельный снимок к пункту не сопоставлен.
- [ ] Нажмите «Открыть RouterOS», откройте условия лицензии MikroTik и после ознакомления выберите «Согласен и запустить». Приложение само проверит наличие образа и при необходимости скачает его с MikroTik. — отдельный снимок к пункту не сопоставлен.
- [ ] Если появилось «Не удалось подключиться к виртуальной CHR», проверка схемы и загрузка образа уже пройдены, но связь приложения с виртуальной машиной не установлена. Этот сбой ещё исследуется; переустанавливать RouterOS или удалять образ не требуется. Сохраните текст ошибки и обратитесь за помощью. — отдельный снимок к пункту не сопоставлен.

### Проверка ping из виртуального MikroTik в Windows

**Изображения в подразделе:** нет.

- [ ] В установленном Windows-приложении откройте лабораторию, выберите поддерживаемую схему и нажмите «Запустить модель». Модель проверяет схему, но сама не отправляет сетевые пакеты. — отдельный снимок к пункту не сопоставлен.
- [ ] После успешной проверки запустите CHR для нужного MikroTik и оставьте её окно открытым. При необходимости отдельно подтвердите загрузку образа и интернет-режим; в нём виртуальная машина может обращаться к компьютеру и локальной сети. — отдельный снимок к пункту не сопоставлен.
- [x] В блоке «Реальный ping из виртуальных устройств» выберите именно запущенный маршрутизатор и выберите адрес из схемы или введите одиночный IPv4-адрес либо DNS-имя. Адрес схемы сам по себе не означает, что целевая VM запущена. Для первого контроля можно ввести LAN-адрес этого MikroTik, указанный в схеме. Это проверит ответ его собственного адреса, но не соединение с ПК. — `assets/img/own/chr-ping-dns-windows.jpg`; проверить визуально и по версии.
- [ ] Нажмите «Отправить ping». Для имени сначала подтвердите DNS-запрос из CHR; если DNS не вернул IPv4, ping не отправляется. Затем проверьте полученный адрес и отдельно подтвердите три ICMP-запроса. Отмена перед ping не отправляет ICMP, но DNS-запрос уже мог быть выполнен. Результат показывает количество ответов от нуля до трёх. — отдельный снимок к пункту не сопоставлен.
- [ ] Если ответов нет, проверьте адрес, маршрут, firewall и разрешение ICMP; ноль ответов не доказывает недоступность цели. Ошибка DNS показывает, что IPv4 не получен; не делайте из неё вывод о состоянии сайта. Задержка пока не измеряется. После изменения схемы проверьте её и запустите новую CHR. — отдельный снимок к пункту не сопоставлен.

### Практика: OpenVPN-сервер для одного клиента

**Изображения в подразделе:** нет.

- [ ] Проверьте сертификаты и время по двум практическим инструкциям раздела System: серверный сертификат с ключом и корректным DNS-именем, учебный CA и отдельный сертификат клиента. Клиент обязан проверять доверенную цепочку и точное имя сервера. — отдельный снимок к пункту не сопоставлен.
- [ ] В IP → Pool создайте учебный пул ovpn-pool 10.44.0.10–10.44.0.99. Убедитесь, что весь VPN-префикс 10.44.0.0/24 не пересекается с LAN, WAN и другими туннелями. — отдельный снимок к пункту не сопоставлен.
- [ ] В PPP → Profiles создайте ovpn-profile: Local Address 10.44.0.1, Remote Address ovpn-pool. Проверьте действующие профили и маршруты; не меняйте общий default-профиль, используемый другими VPN. — отдельный снимок к пункту не сопоставлен.
- [ ] В PPP → Secrets создайте отдельную учётную запись клиента с уникальным сильным паролем, Service ovpn и Profile ovpn-profile. Не публикуйте пароль и не используйте постоянную учётную запись администратора роутера. — отдельный снимок к пункту не сопоставлен.
- [ ] В PPP → OVPN Servers добавьте отдельный сервер или откройте существующий, если версия использует другой интерфейс. Выберите Mode ip, Protocol tcp, Port 1194, сертификат сервера, Default Profile ovpn-profile и Require Client Certificate. Выберите только согласованные клиентом шифр и алгоритм аутентификации; например aes256-cbc и sha256, если обе стороны и политика их поддерживают. Не включайте null или сжатие. — отдельный снимок к пункту не сопоставлен.
- [ ] Оставьте сервер отключённым до проверки. В IP → Firewall → Filter подготовьте узкое input-разрешение TCP 1194 только от разрешённого тестового источника перед соответствующим drop. Forward ограничьте нужным направлением от VPN к одному тестовому узлу LAN; проверьте established/related и обратный путь. Не разрешайте весь input или весь LAN и не добавляйте общие правила поверх неизвестной политики. — отдельный снимок к пункту не сопоставлен.
- [ ] Включите сервер для контролируемой проверки и настройте клиент по следующей инструкции. В PPP → Active и Log проверьте подключение, затем отдельно маршрут, firewall и доступ только к разрешённому тестовому узлу. Отключите тестовый сервер после эксперимента, если он не нужен. — отдельный снимок к пункту не сопоставлен.

### Практика: OpenVPN-клиент, маршрут и проверка

**Изображения в подразделе:** нет.

- [ ] Установите проверенный клиент OpenVPN на тестовый компьютер. Защитите его от посторонних и проверьте актуальную дату и время. Получите безопасно CA .crt, индивидуальный клиентский .crt и зашифрованный .key, а пароль ключа — отдельно. — отдельный снимок к пункту не сопоставлен.
- [ ] В клиентском профиле задайте DNS-имя сервера vpn.example.org вместо учебного примера, TCP и согласованный порт 1194. Настройте использование доверенного CA, клиентского сертификата и ключа; профиль не должен содержать отключение проверки сертификата. — отдельный снимок к пункту не сопоставлен.
- [ ] Включите проверку типа сертификата сервера и точного ожидаемого имени согласно документации вашего клиента, например remote-cert-tls server и verify-x509-name для согласованного Common Name. Одной проверки, что сертификат подписан доверенным CA, недостаточно для проверки конкретного имени сервера. — отдельный снимок к пункту не сопоставлен.
- [ ] Согласуйте шифр aes256-cbc и auth SHA256 с сервером, если они разрешены вашей политикой и поддерживаются обеими версиями. Для OpenVPN 2.6 проверьте data-ciphers и совместимость сервера без NCP; не отключайте проверку сертификатов ради подключения. Сжатие не включайте. — отдельный снимок к пункту не сопоставлен.
- [ ] Импортируйте профиль в клиент и подключитесь с отдельной тестовой сети. Введите индивидуальный логин и пароль PPP; не записывайте их в открытый файл и не публикуйте конфигурацию с ключом. — отдельный снимок к пункту не сопоставлен.
- [ ] Направьте в туннель только сеть 192.168.88.0/24 через поддерживаемую push-route или настройку клиента. Убедитесь в обратном маршруте из LAN через MikroTik и проверьте существующие маршруты и firewall; full-tunnel и IPv6 требуют отдельного проекта. — отдельный снимок к пункту не сопоставлен.
- [ ] Проверьте разрешённый узел LAN, затем попытку к запрещённому узлу и доступ к управлению роутером. В безопасном стенде проверьте отказ с недоверенным сертификатом, неверным именем сервера и неверным паролем; после каждого теста верните корректные данные. По окончании отключите клиент и удалите временные копии ключей согласно политике. — отдельный снимок к пункту не сопоставлен.

### Практика: учебный центр и сертификат сервера

**Изображения в подразделе:** нет.

- [ ] В System → Certificates откройте список и проверьте действующие сертификаты и их назначение. Не заменяйте и не удаляйте существующий CA: от него могут зависеть другие службы. Заранее определите DNS-имя сервера, которое будет использовать клиент. — отдельный снимок к пункту не сопоставлен.
- [ ] Создайте шаблон учебного CA: Name и Common Name, например lab-ca, Key Size 2048, срок согласно плану учебного стенда. На вкладке Key Usage оставьте key-cert-sign и crl-sign; не назначайте ему tls-server или tls-client. — отдельный снимок к пункту не сопоставлен.
- [ ] Сохраните шаблон, выберите его и откройте Sign. Подпишите CA самим собой, не выбирая другой CA. Дождитесь окончания операции; в списке проверьте, что это CA с закрытым ключом. Подписание больших ключей на слабом устройстве может занимать время. — отдельный снимок к пункту не сопоставлен.
- [ ] Создайте отдельный шаблон сервера: Name lab-server, Common Name vpn.example.org и Subject Alt. Name DNS:vpn.example.org, где пример имени заменяется вашим подтверждённым DNS-именем. Выберите ключ 2048 или согласованный политикой, срок и Key Usage digital-signature, key-encipherment и tls-server. — отдельный снимок к пункту не сопоставлен.
- [ ] Сохраните серверный шаблон, выберите Sign и укажите в CA созданный lab-ca. Проверьте issuer, срок, DNS-имя и флаг K закрытого ключа у подписанного серверного сертификата. Сервер использует именно сертификат с соответствующим приватным ключом. — отдельный снимок к пункту не сопоставлен.
- [ ] Экспортируйте клиентам только открытый сертификат CA через Export без export passphrase, если нужен PEM .crt. Сверьте отпечаток CA по независимому доверенному каналу и установите доверие только для этого учебного проекта. Не экспортируйте ключ CA или сервера. — отдельный снимок к пункту не сопоставлен.

### Практика: сертификат клиента и безопасная передача

**Изображения в подразделе:** нет.

- [ ] В тестовой CHR откройте System → Certificates и добавьте отдельный шаблон для одного клиента: Name и Common Name, например lab-client-1; выберите согласованный размер ключа, срок и Key Usage digital-signature и tls-client. — отдельный снимок к пункту не сопоставлен.
- [ ] Сохраните шаблон и выберите Sign с учебным CA lab-ca. Проверьте издателя, срок и наличие закрытого ключа K. Для каждого клиента выдавайте отдельный сертификат; не используйте ключ сервера как клиентский. — отдельный снимок к пункту не сопоставлен.
- [ ] Для учебного клиента выберите сертификат клиента → Export, формат PEM и задайте уникальную сильную export passphrase. RouterOS создаёт .crt и зашифрованный .key в Files; операция экспорта может требовать право sensitive. Не экспортируйте закрытый ключ CA. — отдельный снимок к пункту не сопоставлен.
- [ ] Передайте клиентский .crt и .key, а также только открытый .crt CA по защищённому согласованному каналу; пароль ключа передайте отдельно. Не отправляйте файлы в чат, Git, CI или общие папки и не сохраняйте секреты на снимках экрана. — отдельный снимок к пункту не сопоставлен.
- [ ] После проверки импорта удалите временные экспортированные файлы из Files и временных каталогов по политике организации; обычное удаление не гарантирует надёжного стирания. Проверьте отзыв, сроки и доступность CRL по вашей политике: проверка отзыва по умолчанию не включена. — отдельный снимок к пункту не сопоставлен.
