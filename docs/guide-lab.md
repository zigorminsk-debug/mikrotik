# Переход из учебника в лабораторию

## Что работает

На страницах учебника есть «Проверить на стенде». Нажатие раскрывает доступные функции и ограничения. Подготовленные сценарии есть для первичной настройки и разделов IP, Interfaces, Bridge, Routing и System; в каждой карточке перечислены только выбранные функции, но создаётся и необходимая учебная основа. Wi-Fi, VPN, PPPoE, динамические маршруты, IP Cloud и другие неподдерживаемые функции не переносятся: рядом объясняется почему. Для остальных разделов предлагается честное сообщение о том, что сценарий ещё не реализован; не выдавать этот переход за поддержку всех разделов.

Строится **новая** изолированная схема из одного учебного провайдера, одного MikroTik и ПК. Для гостевого VLAN добавляется второй ПК. В разделах Interfaces, Bridge, Routing и System дополнительно создаются базовые DHCP LAN, Firewall, NAT и DNS-кэш; в первичной настройке и IP они показаны в списке выбора. Адрес статического WAN `198.51.100.2/30` и NTP `192.0.2.123` учебные; NTP синхронизацию не проверяет. Клиентские компьютеры и провайдеры в CHR не запускаются как отдельные виртуальные машины.

Проверка схемы — учебная модель. На Windows можно отдельно нажать «Открыть CHR» в результатах и после независимой проверки плана в main-процессе, согласия и ознакомления с лицензией запустить настройки в **настоящей виртуальной** RouterOS. По умолчанию WAN изолирован. Физический MikroTik не затрагивается; Android и браузер пока только моделируют. Результат открытия — WebFig, а не WinBox. Автоматические снимки WinBox для пользовательской схемы пока отсутствуют.

## Предотвращение конфликтов

Выбор валидируется до замены схемы. Статический WAN и DHCP на одном порту несовместимы; VLAN требует Firewall, DHCP гостевой сети — VLAN, локальная DNS-запись — DNS-кэш. Учебная модель с WAN сейчас требует NAT, а в этом сценарии NAT дополнительно требует Firewall как политика безопасности. При конфликте причина отображается, кнопка перехода отключается; никто не удаляет и не заменяет текущую схему. Недоступная функция не может быть выбрана, рядом указана причина. Если схема уже существует, её замена требует явного подтверждения; отмена оставляет данные нетронутыми. После создания лаборатория проверяет всю модель и Windows-компонент повторно строит план; никаких команд из учебника renderer не передаёт.

## Проверки и дальнейшая работа

`tools/test-guide-lab.js` перебирает все комбинации поддерживаемых чекбоксов и проверяет конфликты, отсутствие побочного запуска, отмену замены, модель и приватный план CHR. `.github/workflows/windows-guide-lab-chr.yml` выполняет несколько конкретных сценариев через интерфейс в одноразовой виртуальной CHR, её REST-верификатор и удаление временного диска. Это не доказательство работы каждой комбинации на реальном оборудовании или в установленном EXE. Добавлять оставшиеся разделы можно только после реализации и реальных проверок; не заменять выбранные функции похожими настройками и не отправлять частичный план при ошибке.
